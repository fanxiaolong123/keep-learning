# 组装 MetaLearn 本地学习手册

把已经完成的知识地图和全部模块收束为一套可连续学习的本地手册。保持较高设计自由度：本技能规定信息关系、导航行为和验收门槛，不规定入口页模板。

## 一、确认组装前提

1. 定位用户指定的知识地图；未指定时，用 `rg --files` 查找文件名含“知识地图”“学习地图”“学习计划”或 `Learn Plan` 的文件。
2. 完整读取知识地图及脚本数据，提取计划内模块数量、顺序、课程边界和完成状态。
3. 找到所有模块文件并逐一对应地图。不得依靠文件名字典序代替地图顺序。
4. 当前环境提供 `get_goal` 时先读取 Goal：只记录与同一知识地图和课程目录匹配的活动 Goal；不得创建新 Goal，也不得修改无关 Goal。
5. 遇到以下情况时停止并请求用户处理：
   - 找不到知识地图或存在多份会改变课程范围的地图。
   - 计划内模块缺失、顺序无法确认或仍处于生成阶段。
   - 目标目录包含多套课程，无法判断哪些页面属于同一手册。

## 二、锁定手册契约

编辑前记录：

- **规范名称**：用户明确指定的名称优先；否则取知识地图主标题。标题含 `｜` 或 `|` 时，默认把分隔符前的部分作为手册名称，后半部分只作副标题或学习目的。
- **页面序列**：知识地图 → 模块一 → 模块二 → …… → 最后模块。
- **内容边界**：只增加入口、导航、必要元数据和本地启动方式；不改教学正文、史实、练习、答案、进度规则和本地存储键。
- **运行边界**：默认纯本地、相对链接、无服务器、无外部运行时依赖。

在临时目录保存待修改页面的原始副本。完成后检查差异，确认所有变化都属于本次组装范围；不要用“看起来没改”代替差异证据。

## 三、读取现有视觉与页面结构

1. 确认环境中已有 `impeccable`；没有时先通过技能发现或安装能力安装，无法安装则停止界面工作。
2. 完整读取并执行 `impeccable` 当前指令。入口页属于新表面时遵循其新页面流程；对既有页面只做窄范围布局适配。
3. 至少检查知识地图、一个普通模块和所有特殊结构页面，例如：
   - 固定顶部栏或固定侧栏。
   - 手机端横向标签栏。
   - 单页站点切换而非长页面滚动。
   - 已有上一站、下一站或结业导航。
4. 先决定每页导航放在哪里，再写代码。不得把同一固定组件机械覆盖到所有页面。

## 四、创建统一入口

新建入口页，不把知识地图改造成总目录：

- 首屏使用规范名称，不用作者、学习目的或上级计划名称取代课程名称。
- 把知识地图设为学习起点，把模块按地图顺序组成连续目录。
- 入口负责导航，不复制或改写模块内容，不制造另一套互相冲突的学习进度。
- 只有在本地文件环境中验证可靠时才加入“继续上次学习”；不要假定不同 `file://` 页面共享本地存储。
- 继承现有课程的视觉世界，但不复制某个模块的章节骨架，也不使用通用卡片墙。

## 五、建立跨页导航

为知识地图和每个模块提供：

1. **首页入口**：在左上角既有标题、品牌标记或学习脊柱附近显示文字“首页”；不能只用无文字图标。手机端同样必须在左上或首屏立即可见，不能藏在横向滚动末端。
2. **连续导航**：提供“上一页｜学习目录｜下一页”。
   - 知识地图的上一页显示为起点或禁用。
   - 最后模块的下一页显示为终点或禁用，不制造循环。
   - “学习目录”返回入口页的目录位置；“首页”返回入口页首屏。
3. **结构适配**：
   - 固定导航不得遮挡保存失败提示、内部标签栏、表单按钮或安全区域。
   - 页面已有固定底栏时，跨页导航改放结业区或调整到互不遮挡的位置。
   - 页头空间不足时，用“首页”替换纯装饰标记，不同时堆叠两个标记。
   - 键盘用户能在正文前通过跳转链接直达跨页导航。
4. **实现选择**：页面结构相近时可共享本地 CSS 和 JavaScript；结构差异明显时按页适配。共享资产是维护手段，不是固定视觉模板。

## 六、提供本地启动方式

1. 入口文件使用稳定、简短的文件名，例如 `index.html`。
2. 在 macOS 上生成“打开〈规范名称〉.command”：优先用已安装的 Chrome 打开入口，否则使用默认浏览器。
3. 使用绝对解析启动器自身目录的方式定位入口，正确处理空格和中文路径，并设置可执行权限。
4. 不启动本地服务器，除非静态文件确实无法满足需求且用户明确同意增加运行步骤。

## 七、验证与独立审查

编辑完成后完整读取 [references/acceptance.md](references/acceptance.md)，然后：

1. 运行：

   `node <本技能目录>/scripts/validate-handbook.mjs <目录> --entry <入口文件> --map <知识地图> --modules <按顺序列出的模块文件> --launcher <启动器> --title <规范名称>`

   将 `<本技能目录>` 解析为当前 `SKILL.md` 所在目录，不要按项目工作目录猜测脚本位置。

2. 检查原始副本与成品差异，确认教学内容未被改写。
3. 使用浏览器或截图能力验证桌面和小屏关键状态。若安全策略阻止本地 `file://`，不得绕过；提供静态替代证据并明确说明未完成浏览器视觉验证。
4. 主代理首轮自检后，派出三个不直接编辑文件的独立子代理：
   - **地图与课程审查**：核对名称、模块数量、顺序、边界和正文不变。
   - **界面与交互审查**：必须使用 `impeccable`，检查首页可见性、遮挡、页头拥挤、键盘和小屏。
   - **技术与本地运行审查**：检查相对链接、脚本时序、首尾状态、启动器和静态验证证据。
5. 只把知识地图、原页面、成品和验收标准交给子代理，不提供主代理的预期结论。主代理核实发现、修复问题并重新运行相关检查。
6. 所有编辑结束后，只运行一次 `impeccable` 最终设计检测。

## 八、交付

简洁报告：

- 入口页、共享导航资产和启动器路径。
- 课程规范名称与页面顺序。
- 验证脚本、差异检查和三个独立审查的实际结果。
- 未完成的浏览器视觉验证或其他限制。

若存在与本课程匹配的活动 Goal，只有本技能全部验收完成且没有必需工作遗留时，才调用 `update_goal({status: "complete"})`；没有活动 Goal 时不调用。不得在缺少模块、验证失败或仍等待必要权限时提前完成 Goal。

只删除本技能创建的临时副本，不删除或覆盖用户原文件。
